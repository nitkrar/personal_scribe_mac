## New issues (the revision introduced)

1. **#078.30 is now the mega-step C2 was supposed to prevent.** "Atomic rename" of `Transcriber2 → Transcriber` and `RecipeWorkflowMode → WorkflowMode` (with concurrent `Transcriber → LegacyTranscriber` and `WorkflowMode → LegacyWorkflowMode`) touches *both* core protocol files, *both* core mode-type files, plus mechanical updates to "every adapter, provider protocol, registry, and existing tests' imports." File listing line 299 names 4 files explicitly but ends with "plus mechanical references in adapters, provider protocol, registry" — that's the same "list the exact files in advance" anti-pattern v1's #078.16 had. Fix: split #078.30 into #078.30a (rename `Transcriber` family — protocols + adapters + provider + tests) and #078.30b (rename `WorkflowMode` family — types + registry + builder + tests), with per-file checkboxes in each. OR keep atomic but enumerate every file with a checkbox in #078.30.

2. **#078.7's `testEngineKindMatchesStoredKindForEveryCatalogDescriptor` is tautological at Phase A.** The catalog at this phase still passes both `engine:` and `kind:` to `ModelDescriptor` constructor, where the test author controls both fields. Until #078.37 deletes the stored field and forces the catalog to stop passing `kind`, the test only proves "the catalog is internally consistent with itself" — not "the engine→kind mapping is correct." Fix: rename to `testEngineKindMappingMatchesCatalogConvention` to signal it's a convention check, not a mapping correctness check; the actual behavioral oracle is #078.38's `testActiveDescriptorForKindReturnsCorrectEngineMatch` which only fires post-deletion. Or add a separate test that hardcodes the expected mapping (e.g., `XCTAssertEqual(TranscriptionEngine.parakeetTDT.kind, .asr)`) without going through any descriptor.

3. **#078.31a's "existing tests must keep passing through this rewire" lacks an explicit cutover-correctness test.** This is the single behavioral pivot of the entire plan: orchestrator now reads from `WorkflowModeRegistry` instead of `ServiceBackedActiveModeProvider`. The Phase G runtime gate covers it, but no unit test pins "orchestrator constructs a recipe from registry on session start, not from legacy provider." #078.29 has `testOrchestratorBuildsRecipeAtSessionStart` — confirm at #078.31a that this test fires against the *registry*-injected orchestrator (it should, but the per-step test list says "no new tests"). Fix: in #078.31a's checklist, add an explicit assertion that #078.29's tests now run with `WorkflowModeRegistry`-backed `AppComposition`, not the legacy provider.

4. **Phase H.6 step number drift.** Review-1 referenced "#078.6 deletes `voiceModelID/aiModelID/systemPrompt`" — but in v2, #078.6 is `SpeakerDiarizer`. The stored-`kind` removal is now #078.37 (Phase H), and the legacy field removal happens at #078.36 (`LegacyWorkflowMode` delete). This is fine for the plan but means anyone reading review-1 next to v2 will be confused. Not a blocker — just flag it for the user's mental model.
