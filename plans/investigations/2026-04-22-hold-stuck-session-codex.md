# Hold-Stuck Session Trace

- Hold-start: `PersonalScribeAppMain` builds the hotkey monitor and injects `onHoldStartVisibilityPush`, which forces the pill to `.holdToRecord` before session work starts (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:154-159`). `AppComposition.makeGlobalHotkeyMonitor` wires `onHoldStart` to that UI push plus `Task { await coordinator.startIfIdle() }` (`Sources/PersonalScribeAppKit/Composition/AppComposition.swift:98-114`). `startIfIdle()` only acts from `.idle` and routes through `performStart() -> performToggle() -> pipeline.toggleCapture()` (`Sources/PersonalScribeSession/SessionCoordinator.swift:109-115,192-204`). The pipeline does `capture.start()` and only then publishes `.recording` (`Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift:159-190`).

- Hold-release: `GlobalHotkeyMonitor` owns a separate `isHolding` flag; on key-up, if that flag is set, it clears it and fires `onHoldRelease()` (`Sources/PersonalScribeAppKit/Hotkeys/GlobalHotkeyMonitor.swift:80,345-360,385-395`). Composition maps that to `Task { await coordinator.stopIfRecording() }` (`Sources/PersonalScribeAppKit/Composition/AppComposition.swift:115-118`). `stopIfRecording()` is just a guard plus `performStop() -> performToggle()` (`Sources/PersonalScribeSession/SessionCoordinator.swift:117-123,196-204`). In the pipeline, `.recording` means `toggleCapture()` stops capture and proceeds into `.transcribing`/`.idle` (`Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift:73-90,205-236,305-312`).

- Toggle: pill taps call `Task { await coordinator.toggle() }` (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:96-103`). Hotkey taps call `onToggle()` from `handleKeyUp()` when the press stays under the hold threshold (`Sources/PersonalScribeAppKit/Hotkeys/GlobalHotkeyMonitor.swift:363-382`), and composition maps that to `coordinator.toggle()` (`Sources/PersonalScribeAppKit/Composition/AppComposition.swift:103-108`). `toggle()` switches on one shared `SessionState`: `.idle` starts, `.recording` stops, `.transcribing/.error` still go through `performToggle()` (`Sources/PersonalScribeSession/SessionCoordinator.swift:98-106`). The coordinator has no hold-specific state; `SessionState` is only `.idle/.recording/.transcribing/.error` (`Sources/PersonalScribeCore/SessionState.swift:1-5`).

- Esc: `EscapeKeyMonitor` is stateless; the call site checks only pill visibility (`.holdToRecord` or `.recording`) before acting (`Sources/PersonalScribeAppKit/Hotkeys/EscapeKeyMonitor.swift:26-31,96-103`; `Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:134-143`). If the gate passes, Esc does `viewModel.cancel()` and then unconditionally `coordinator.toggle()` (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:140-142`). `cancel()` is UI-only; it sets `.cancelled` and never touches the coordinator (`Sources/PersonalScribeAppKit/Overlay/PillOverlayViewModel.swift:94-115`). The code comment explicitly says this is not a true cancel path and that a future `cancelRecording()` is needed (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:126-133`).

- Divergent state: hold exists in `GlobalHotkeyMonitor.isHolding` and pill UI `.holdToRecord`, not in coordinator state (`Sources/PersonalScribeAppKit/Hotkeys/GlobalHotkeyMonitor.swift:80,357-359,389-395`; `Sources/PersonalScribeCore/AppStore/PillVisibilityState.swift:6-12`; `Sources/PersonalScribeCore/SessionState.swift:1-5`). The app store derives any active session as `.recording` (`Sources/PersonalScribeCore/AppStore/AppStore.swift:310-317`), but the view model intentionally suppresses incoming `.recording` while already showing `.holdToRecord` (`Sources/PersonalScribeAppKit/Overlay/PillOverlayViewModel.swift:74-83`). So the UI can remain “hold” while the coordinator is plain `.recording`.

- Hypotheses, ranked:
1. Most likely: async race. `onHoldStart` and `onHoldRelease` spawn separate `Task`s (`Sources/PersonalScribeAppKit/Composition/AppComposition.swift:109-118`). Because `capture.start()` happens before `.recording` is published (`Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift:165-190`), `stopIfRecording()` can run while `currentState` is still `.idle` and no-op (`Sources/PersonalScribeSession/SessionCoordinator.swift:117-122,307-326`).
2. Next: Esc trusts stale pill visibility, not coordinator state, then calls `toggle()`. If the coordinator is already `.idle` or `.error`, Esc starts a new normal toggle session by definition (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:134-143`; `Sources/PersonalScribeSession/SessionCoordinator.swift:98-106`; `Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift:73-89`).
3. Lower confidence: any dropped release callback leaves `isHolding`/UI state and coordinator state with no shared hold token to reconcile them (`Sources/PersonalScribeAppKit/Hotkeys/GlobalHotkeyMonitor.swift:345-359`; `Sources/PersonalScribeCore/SessionState.swift:1-5`).
