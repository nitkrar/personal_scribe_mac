# #042 AX probe review — Codex pass (2026-04-22)

## Root cause confirmation
`ClipboardBatchOutput.deliverBatch` now auto-pastes only when Accessibility is trusted and `focusedElementHasCursor()` returns `true`; otherwise it leaves the transcript on the clipboard (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:107-129`). The live probe accepts only `AXInsertionPointLineNumber`, `AXSelectedText`, or role `AXTextField` / `AXTextArea` / `AXComboBox` (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:220-258`), and `attributeIsReadable` requires `.success` plus a non-`nil` value (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:261-267`). Apple’s AX headers say `AXSelectedText` is required for editable text elements, `AXRole` is required for all elements, and the generic fallback role is `AXUnknown` (`/Users/nitinkum/Projects/nitkrar/personal_scribe/plans/investigations/2026-04-22-042-ax-sdk-dump.txt:32-71,171-176`; `/Applications/Xcode_26.2.0_17C52_fb.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/ApplicationServices.framework/Frameworks/HIServices.framework/Headers/AXAttributeConstants.h:202-210`). So the bug is confirmed: the focused AX element that Ninimma sees in Sublime is not presenting as a standard editable text element. The exact role is not verifiable here; `AXUnknown` is the strongest guess, with `AXGroup` still plausible.

## Option 1 — PID inequality
- Concrete mechanism: keep the current system-wide focused-element lookup, then call `AXUIElementGetPid(focused, &pid)` and paste whenever that pid is not Ninimma’s pid (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:220-232`; `/Users/nitinkum/Projects/nitkrar/personal_scribe/plans/investigations/2026-04-22-042-ax-sdk-dump.txt:5-18`).
- Pros: fixes custom-drawn editors without guessing roles; still blocks paste when the focused AX element actually belongs to Ninimma.
- Cons / failure modes: this stops checking “is text-like.” A foreign Finder sidebar, Dock item, notification surface, or other non-text control becomes paste-eligible just because it is outside Ninimma.
- Feasibility: high. The API exists; only the probe seam needs to widen beyond `@MainActor () -> Bool` (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:12,32,60-61`).

## Option 2 — extended roles
- Concrete mechanism: keep the current attribute checks, then widen the role allowlist beyond `AXTextField` / `AXTextArea` / `AXComboBox` (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:241-255`).
- Pros: smallest code diff that preserves the current “focused element should look text-ish” intent.
- Cons / failure modes: `AXUnknown` is the generic fallback role, `AXGroup` is a generic container, and on this SDK “WebArea” is AppKit’s `NSAccessibilityWebAreaRole`, a document surface rather than an editable-field role (`/Applications/Xcode_26.2.0_17C52_fb.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/ApplicationServices.framework/Frameworks/HIServices.framework/Headers/AXAttributeConstants.h:202-210`; `/Users/nitinkum/Projects/nitkrar/personal_scribe/plans/investigations/2026-04-22-042-ax-sdk-dump.txt:177-187`; `/Applications/Xcode_26.2.0_17C52_fb.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/AppKit.framework/Versions/C/Headers/NSAccessibilityConstants.h:555`). There is no runtime evidence here that Sublime, VS Code, or Chrome stop at those roles.
- Feasibility: medium. Easy patch, weak justification.

## Option 3 — revert to bundle-ID
- Concrete mechanism: restore the commented `resolveTarget()` path and gate paste on `frontmostApplication.bundleIdentifier != AppBrand.bundleIdentifier` (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:132-165`; `Sources/PersonalScribeAppKit/Paste/PasteRouting.swift:19-21`; `Sources/PersonalScribeCore/AppBrand/AppBrand.swift:3-6`).
- Pros: simplest fix; it removes the under-inclusive AX role/attribute dependency entirely.
- Cons / failure modes: it reintroduces false self-frontmost windows during the stop/transcribe/paste window. The pill path is much safer now because the panel is non-activating, non-key, and non-main (`Sources/PersonalScribeAppKit/Overlay/PillOverlayPresenter.swift:59-84,245-247,478`), but the status-item stop path is still manually unverified (`Tests/PersonalScribeAppKitTests/ManualPillOverlayVerification.md:190-193`).
- Feasibility: high. The supporting provider fields and `OutputTarget.selfFrontmost` path still exist (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:25-27,42-44`; `Sources/PersonalScribeCore/Output/OutputTarget.swift:1-4`; `Sources/PersonalScribeAppKit/MenuBar/MenuBarSceneModel.swift:151-156`).

## Alternative options
Best non-ticket option: bundle-ID primary, AX-PID rescue only when frontmost is self. If the frontmost bundle is not Ninimma, paste immediately. If it is Ninimma, inspect the focused element pid and still paste when AX says focus belongs to another process (`Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:25-27,42-44,132-165,220-232`; `Sources/PersonalScribeAppKit/Paste/PasteRouting.swift:19-21`; `/Users/nitinkum/Projects/nitkrar/personal_scribe/plans/investigations/2026-04-22-042-ax-sdk-dump.txt:5-18`). This avoids role guessing, fixes custom editors when frontmost, and still guards the “Ninimma briefly frontmost but real AX focus stayed elsewhere” case. `AXParent` walks or `AXNumberOfCharacters` are weaker primary fixes because they still assume the focused element participates in the text AX contract Sublime is already violating (`/Users/nitinkum/Projects/nitkrar/personal_scribe/plans/investigations/2026-04-22-042-ax-sdk-dump.txt:20-30,52-63`).

## Option 3 regression risk — detailed audit
- Hotkey release path: safe. `onToggle`, `onHoldStart`, and `onHoldRelease` only dispatch to coordinator methods; there is no window show or app activation on that path (`Sources/PersonalScribeAppKit/Composition/AppComposition.swift:103-118`).
- Pill click stop path: safe by code shape. The click handler only calls `coordinator.toggle()`, and the pill panel is explicitly `.nonactivatingPanel`, `canBecomeKey = false`, `canBecomeMain = false` (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:96-103`; `Sources/PersonalScribeAppKit/Overlay/PillOverlayPresenter.swift:59-84,245-247`).
- Menu-bar status-item Stop click path: unknown. The action itself only routes to `sceneModel.handleRecordButtonTap()` and then `coordinator.toggle()`, but NSStatusItem/NSMenu focus behavior is AppKit-owned and MV-NAP-3 is still open (`Sources/PersonalScribeAppKit/MenuBar/StatusItemController.swift:131-136`; `Sources/PersonalScribeAppKit/MenuBar/MenuBarSceneModel.swift:107-124`; `Tests/PersonalScribeAppKitTests/ManualPillOverlayVerification.md:190-193`).
- Escape / cancel paths: safe. Esc just flips pill UI state and calls `coordinator.toggle()`; no activation call is involved (`Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:134-143`; `Sources/PersonalScribeAppKit/Hotkeys/EscapeKeyMonitor.swift:26-31,96-103`).
- Settings / unified window open during recording: regressed by design, but truthfully so. `showWindow` makes the window key and activates Ninimma, and onboarding / Settings entry points call it (`Sources/PersonalScribeAppKit/UnifiedWindow/UnifiedWindowController.swift:149-151`; `Sources/PersonalScribeAppKit/Composition/PersonalScribeAppMain.swift:203-210,267-270,291-293`).
- App-switcher during recording: timing-dependent but not code-buggy. The reverted check samples `NSWorkspace.shared.frontmostApplication` at delivery time, so Cmd-Tab simply makes the final frontmost app decisive (`Sources/PersonalScribeAppKit/Paste/PasteRouting.swift:19-21`; `Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:154-164`).

## Recommended option
Recommend the hybrid alternative above, confidence medium. It fixes the confirmed under-inclusive AX probe without betting on guessed roles, and it narrows the self-frontmost regression risk better than a pure bundle-ID revert.
