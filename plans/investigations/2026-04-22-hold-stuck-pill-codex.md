1. Most likely: async race. Release can therefore fire, no-op, then later wedge on sticky `.recording`.
2. Less likely: real missed `onHoldRelease` from the event path. If key-up never reaches `handleKeyUp`, there is no secondary cleanup; the monitor only calls `onHoldRelease()` from key-up in [GlobalHotkeyMonitor.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/Hotkeys/GlobalHotkeyMonitor.swift#L345C1).
3. Least likely: duplicate-pill/z-order bug. Code points to one pill panel, not two; only the response card is a separate panel.
