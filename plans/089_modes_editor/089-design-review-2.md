# #089 DESIGN review 2 — codex

## Summary
The design’s delivery seam does not exist in current wiring, and one schema delta is internally inconsistent with current core types. `MenuBarSceneModel` cannot reach a frozen `BoundRecipe`, while `PreferenceKeys.vadAutoStopEnabled` and `SettingKey(rawKey:)` do not exist.

## Objections (ranked, strongest first)

### 1. Delivery path cannot read the session-bound recipe as written
**Severity**: critical  
**Where**: `DESIGN.md` “Delivery path resolution (L-24)” + [Sources/PersonalScribeAppKit/MenuBar/MenuBarSceneModel.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/MenuBar/MenuBarSceneModel.swift:12), [Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeSession/Pipeline/Orchestrator/SessionPipelineOrchestrator.swift:21), [Sources/PersonalScribeSession/AppStore/SessionCoordinator+AppStore.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeSession/AppStore/SessionCoordinator+AppStore.swift:4)  
**Issue**: `MenuBarSceneModel` only owns `AppStore`, `SessionCoordinator`, and `OutputService`; it has no `sessionPipeline` handle. `SessionCoordinatorAppStoreAdapter` streams snapshots only, and `boundRecipe` is a `private` orchestrator field. The proposed caller path does not compile.  
**Suggested fix**: Add an explicit coordinator/session seam for resolved delivery settings; do not have AppKit reach into orchestrator private state.

### 2. The new delivery settings still do not encode the recipe truth source
**Severity**: major  
**Where**: `DESIGN.md` “Delivery path resolution (L-24)” + [Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/Output/ClipboardBatchOutput.swift:71), [Sources/PersonalScribeSession/SessionCoordinator.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeSession/SessionCoordinator.swift:53), [Tests/PersonalScribeSessionTests/WorkflowMode/WorkflowModeRegistryTests.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Tests/PersonalScribeSessionTests/WorkflowMode/WorkflowModeRegistryTests.swift:53)  
**Issue**: `ResolvedDeliverySettings` carries only booleans, but `ClipboardBatchOutput` always writes the clipboard. Current code permits recipes with `.frontmostPaste` and no `.clipboard` sink. Under the proposed API, those shapes still clipboard-write, so `BoundRecipe.outputSinks` is not actually the delivery truth source.  
**Suggested fix**: Carry enough resolved sink shape to represent sink presence, not just the two booleans.

### 3. The schema/PreferenceKeys delta is wrong for current core APIs
**Severity**: critical  
**Where**: `DESIGN.md` “Schema deltas” + [Sources/PersonalScribeCore/Preferences/PreferenceKeys.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeCore/Preferences/PreferenceKeys.swift:16), [Sources/PersonalScribeCore/Preferences/SettingKey.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeCore/Preferences/SettingKey.swift:32)  
**Issue**: `PreferenceKeys` currently exposes only `vadSilenceThreshold`, `vadShowStoppingWarning`, `vadShowAutoStoppedNotification`, and `clipboardRestoreEnabled`; there is no `vadAutoStopEnabled` or `autoPasteEnabled`. The sample also uses `SettingKey(rawKey:...)`, but the actual initializer is `SettingKey(key:default:)`. As written, it does not compile.  
**Suggested fix**: Lock the missing keys explicitly and correct the constructor/signature names in the design.

### 4. “Reuse HotkeyRecorder verbatim” is not believable
**Severity**: major  
**Where**: `DESIGN.md` “Hotkey path (L-21..L-23)” + [Sources/PersonalScribeAppKit/Settings/HotkeyRecorder.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/Settings/HotkeyRecorder.swift:11), [Sources/PersonalScribeAppKit/Settings/ReservedInAppHotkeys.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/Settings/ReservedInAppHotkeys.swift:37), [Sources/PersonalScribeAppKit/Composition/AppComposition.swift](/Users/nitinkum/Projects/nitkrar/personal_scribe/Sources/PersonalScribeAppKit/Composition/AppComposition.swift:173)  
**Issue**: Recorder init takes only `currentPreference`, `onConfirm`, `onCancel`; collision logic is a static `reservationReason(for:)` call with no injected mode-hotkey set. The monitor factory also has no registry dependency today. The design needs API threading, not verbatim reuse.  
**Suggested fix**: Specify the dependency seam for existing mode-hotkeys and registry-driven dispatch.
